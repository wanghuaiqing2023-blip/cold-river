# 大模型能力缺陷与专业 Agent 的机会

> 日期：2026-08-10
>
> 主题：大模型能力缺陷是否反而为专业 Agent 创造了机会，以及 AGI 时代专业 Agent 是否会消失。

## 讨论起点

一个重要判断是：

> **大模型的能力缺陷反而是机会。大模型的能力缺陷提供了大量在专业领域制作专业 Agent 的机会。**
>
> 可以进一步设想：如果 Agent 最终达到通用 AGI 的水准，那么今天很多专门化、特化的 Agent 可能都会消失。

这个判断基本成立，但需要进一步区分两类完全不同的 Agent。

---

## 一、今天大量专业 Agent 的价值，本质上来自模型能力缺口

今天的大模型虽然已经很强，但依然存在大量系统性缺陷：

- 长程规划不稳定；
- 状态保持能力有限；
- 在几十步甚至几百步任务中容易发生目标漂移；
- 工具调用存在错误积累；
- 对失败的识别和恢复能力不足；
- 自我验证能力有限；
- 对领域规则、权限、流程和边界缺乏可靠遵守能力；
- 在开放环境中很难稳定判断何时继续、回滚或停止。

因此，当前大量 Agent Engineering 的工作，本质上是在用系统结构补偿模型能力缺陷。

例如：

| 模型缺陷 | Agent / Harness 的补偿机制 |
| --- | --- |
| 长程规划弱 | Planner、Task Decomposition |
| 状态保持弱 | State、Checkpoint、Memory |
| 容易幻觉 | Verifier、Grounding、RAG |
| 工具调用不稳定 | Typed Tool、权限控制、Sandbox |
| 失败后不会恢复 | Retry、Rollback、Failure Recovery |
| 不知道是否完成 | Evaluation、Termination Condition |
| 容易重复或遗漏 | Progress Tracking、Task Ledger |
| 无法稳定自我改进 | Trace → Diagnose → Modify → Evaluate |

因此可以把今天的一类 Agent 机会理解为：

> **基础模型做不到的地方，就是 Agent 工程可以创造价值的地方。**

这是一种非常现实的“能力缺口机会”。

---

## 二、如果 AGI 出现，确实会消灭大量“能力补偿型 Agent”

需要区分第一类 Agent：**能力补偿型 Agent**。

它们存在的主要原因是基础模型本身还不够强，例如：

- 因为模型不会规划，所以额外增加 Planning Agent；
- 因为模型记不住，所以增加 Memory Agent；
- 因为模型不会稳定调用多个工具，所以设计复杂 Router；
- 因为模型编码能力不足，所以通过大量 Prompt、Workflow、规则进行补偿；
- 因为模型不会可靠验证，所以外置大量 Critic / Judge / Reflection 机制。

如果未来模型本身天然拥有：

- 强大的长程规划能力；
- 稳定的长期记忆；
- 自主工具学习能力；
- 自我验证能力；
- 长程执行能力；
- 失败识别和恢复能力；
- 稳定的停止判断；

那么今天很多复杂 Agent Framework 的确可能会迅速被基础模型吸收。

换句话说：

> **很多今天看起来非常复杂的 Agent 架构，可能只是模型能力不足时期的“脚手架”。**

下一代基础模型能力每提升一次，都可能直接吞掉一部分 Agent Framework 的价值。

这意味着：

> 如果一个 Agent 产品的全部壁垒只是“用 20 个 Prompt、5 个 Router 和几层 Reflection，让当前模型提高 20%”，那么这种壁垒可能非常脆弱。

一次基础模型升级就可能让它失去意义。

---

## 三、但 AGI 不会消灭所有专业 Agent

第二类 Agent 是：**环境 / 制度 / 专业系统型 Agent**。

这类 Agent 的存在，并不是因为模型“不够聪明”，而是因为现实世界本身具有复杂结构。

例如一个医疗 Agent，即使其核心模型已经达到 AGI 水平，仍然必须面对：

- 医院信息系统；
- 医疗法规；
- 患者权限；
- 医生与护士的工作流程；
- 审计要求；
- 临床责任边界；
- 医疗设备和数据接口。

金融 Agent 仍然必须面对：

- 交易系统；
- 风控规则；
- 监管要求；
- 权限体系；
- 企业内部数据；
- 审计和合规要求。

Coding Agent 仍然必须面对：

- Repository；
- CI/CD；
- Issue / PR；
- Coding Standards；
- 权限系统；
- Deployment；
- Production Environment；
- 团队协作规则。

这些东西不会因为 AGI 更聪明而消失。

即使是一个极其聪明的人类专家，进入一家新的医院、法院、芯片厂、证券公司或一个百万行代码项目，也不能立刻自由行动。

他仍然需要：

> **权限、流程、工具、状态、知识、审计、验证和责任边界。**

因此，更准确的判断应该是：

> **AGI 会大量消灭“为了补偿模型智力不足而存在的 Agent”，但不会消灭“把通用智能嵌入现实专业系统的 Agent”。**

---

## 四、Agent 的本质可能发生迁移

今天的 Agent 很大程度上可以理解为：

> **给一个还不够强的 LLM 安装外骨骼。**

Planner、Memory、Reflection、Router、Verifier、Workflow 等机制，很多都是这个“外骨骼”的组成部分。

而在更强模型甚至 AGI 时代，Agent 更可能变成：

> **把通用智能嵌入某个现实系统的运行容器。**

也就是说，Agent 的重点会从：

```text
如何让模型具有足够的智能
```

逐渐迁移到：

```text
如何让一个已经足够智能的模型
在特定环境中
按照正确权限
维护正确状态
遵循正确流程
获得正确反馈
接受正确验证
承担明确责任
可靠地完成工作
```

这是两个完全不同的问题。

---

## 五、一个看似矛盾但可能非常重要的趋势

未来可能出现：

> **模型越来越强，Agent Framework 越来越简单，但 Agent Engineering 越来越重要。**

原因是，模型能力提高之后，大量用于“教模型如何思考”的脚手架可能不再需要。

但与此同时，模型能够承担的现实任务会越来越复杂，它需要接入的系统也会越来越深。

工程重点可能从今天的：

```text
70%：想办法让模型完成任务
30%：接入现实系统
```

逐渐迁移到：

```text
10%：让模型理解任务
90%：定义环境、权限、状态、反馈、验证和责任边界
```

这类似于 CPU 越来越强，并没有让操作系统消失；数据库越来越智能，也没有让 Schema、Transaction、Permission 和 Consistency 消失。

**智能越强，它能够控制的现实系统越复杂；如何把智能安全、可靠、可验证地嵌入系统，反而会变得更加重要。**

---

## 六、可以把 Agent 的机会分成两层

一个非常有用的抽象是：

> **LLM 的能力缺陷，创造了这一代 Agent 的机会；现实世界的结构复杂性，则创造了 Agent 的长期机会。**

### 第一层：短中期机会——模型能力缺陷

典型问题：

- 模型不会规划；
- 模型记忆不足；
- 模型不会验证；
- 模型不能稳定调用工具；
- 模型无法长程执行；
- 模型无法稳定完成复杂工作流。

这些问题会随着基础模型升级不断缩小。

### 第二层：长期机会——现实系统的结构复杂性

典型问题：

- 任务状态如何表示；
- 权限如何定义；
- 子任务如何验证；
- 多主体如何协调；
- 失败如何恢复；
- 谁承担责任；
- 如何审计；
- 如何建立反馈闭环；
- 如何判断系统真的完成了目标；
- 如何把人置于正确的循环位置。

这些问题不会因为模型智力提高而自然消失。

---

## 七、对 Agent 研究方向的启示

因此，在选择 Agent 研究方向时，可以使用一个非常有价值的问题进行筛选：

> **如果基础模型能力提高 100 倍，这个问题还存在吗？**

如果答案是“不存在”，那么它可能主要是当前模型能力不足产生的临时机会。

如果答案仍然是“存在”，那么它更可能触及 Agent Engineering 的长期核心问题。

例如以下问题具有明显的长期价值：

- 长程任务如何表示状态；
- 大任务如何递归分解；
- 子任务如何显式验证；
- Execution Trace 如何评价；
- Agent 如何知道自己失败；
- 封闭环境如何定义；
- Benchmark 如何隔离模型能力与 Harness 能力；
- 人如何插入长程循环；
- 如何定义 Stopping Condition；
- 如何保证任务没有被遗漏；
- 如何定义任务完成的客观判据。

这些问题很多并不是“模型够不够聪明”的问题，而是：

> **智能系统应该如何被组织。**

---

## 八、进一步形成一个研究框架

与其直接问：

> “怎样造一个更聪明的 Agent？”

更好的问题可能是：

> **对于某一类任务，Agent 成功究竟需要哪些基础能力和系统条件？**

可以采用下面的研究流程：

```text
任务 T
  ↓
分析成功所需基础能力
  ↓
A：状态保持
B：任务分解
C：局部规划
D：失败恢复
E：验证
F：停止判断
  ↓
为每一种能力设计最小实验环境
  ↓
分别测试基础模型能力
  ↓
发现模型真实能力缺口
  ↓
再决定 Harness 应该补什么
  ↓
重新评估
```

这种方法有两个优点。

第一，它不会被某个具体 Agent Framework 牵着鼻子走。

第二，它能够明确区分：

> **哪些能力来自模型本身，哪些能力来自 Harness。**

这对于真正理解 Agent 的能力边界非常关键。

---

## 九、最终结论

这次讨论可以浓缩成三句话：

> **1. 大模型的能力缺陷不是单纯的坏消息，而是当前专业 Agent 最大的机会来源之一。**
>
> **2. AGI 会吞掉大量“能力补偿型 Agent”，但不会消灭现实世界中的专业智能系统。**
>
> **3. Agent Engineering 的长期核心，不一定是让模型变聪明，而是研究如何把通用智能组织成一个可靠、可验证、可控制、能在复杂现实系统中工作的智能体。**

进一步说：

> **真正值得长期研究的，不是某个 Agent Framework，而是“通用模型与专业智能系统之间的边界”。**

这条边界如何随着基础模型能力不断推进而移动，可能正是未来 Agent Engineering 最重要的研究问题之一。
